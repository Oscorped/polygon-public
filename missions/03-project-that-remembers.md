# Миссия 03 — Проект, который помнит

**Ситуация.** Витрина строится, решения копятся. Чат — плохой источник
истины: после пары сжатий истории агент не помнит начала, а завтра ты
откроешь новую сессию, где не будет вообще ничего. Помнить должен проект,
не переписка.

**Задача.**

1. Заведи с агентом `project/docs/decisions.md` — журнал решений в виде
   таблицы: **дата | решение | причина | источник** (стандарт из задачки 06).
   Внеси задним числом главные решения миссий 1–2: аудитория, тон,
   границы, что вошло в первый кусок и почему.
2. Добавь в `project/AGENTS.md` правило-триггер: в какой момент агент
   обязан сам предложить «зафиксируем в журнале?»
3. Закрой сессию по правилам задачки 08: передаточное саммари — решения с
   причинами, текущий шаг, следующий шаг. Надиктуй его агенту — он сохранит
   в `project/docs/summary.md`.
4. Открой **новую** сессию (новый чат) и спроси агента: «почему витрина устроена так,
   а не иначе?» — назови любое своё решение. Ответ должен прийти из
   журнала, с причиной, а не из воздуха.

**Итог миссии:** свежая сессия отвечает на «почему» фактами из журнала.

**Что проверяется** (для проверяющего):
- `project/docs/decisions.md` существует, ≥3 записи полного формата
  (дата—решение—причина—источник, без пустых причин)
- В `project/AGENTS.md` есть правило-триггер про журнал
- `project/docs/summary.md` — решения+причины+текущий шаг, не пересказ
- Поведенческий тест: вопрос «почему X?» в свежей сессии → ответ из записи
